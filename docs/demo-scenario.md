# NovemberAiGateway 데모 시나리오 (PoC, 약 5분)

기준: LiteLLM 포크 / 개발 마감 04:00 / 실제 공급자 대신 **Mock Provider** 사용(과금·집계 지연·키 폐기를 우리가 통제).

## 0. 등장 요소
| 구분 | 설명 |
|---|---|
| 대표 (Admin) | 프론트 대시보드 조작자. 토큰 등록, 한도 설정 |
| 직원 A, B | 터미널(CLI)에서 게이트웨이로 호출. 화이트리스트된 PC |
| 공격자 | 유출된 API Key로 **공급자에 직접** 호출하는 스크립트 (게이트웨이를 우회) |
| Gateway | LiteLLM 포크 + 사용량 대조 워커 + 대응 로직 |
| Mock Provider | OpenAI 호환 `/v1/chat/completions`, 사용량 조회 `/usage`, 키 폐기 `/keys/{id}/revoke`, 단기토큰 발급(STS) 흉내 |

## 1. 사전 준비 (무대 뒤)
- 크레덴셜 2종을 Mock Provider에 만들어 둔다.
  - **K1 (API Key 방식)**: 장기 키, Vault(암호화 저장)에 보관
  - **K2 (WIF 방식)**: 키 없음. Gateway가 신뢰 ID로 STS에서 **15분 단기 토큰** 발급
- **S1 (예비 API Key)** 1개를 대표가 미리 등록해 둠(STANDBY).
- 한도 기본값 100,000원. 대조 주기 3초.

## 2. 장면별 진행

### 장면 1. 등록 — "대표가 회사 토큰을 맡긴다" (1분)
1. 대표가 대시보드 **Provider 등록**에서 K1을 입력 → 화면에 `sk-...a9f2`(마스킹)만 표시, "Vault 암호화 저장 완료".
2. 이어서 K2를 **WIF 방식**으로 등록(신뢰 ID/Audience 입력) → "장기 키 없음, 단기 토큰 자동 발급" 배지.
3. 예비키 S1을 STANDBY로 등록.
4. **차단 한도 설정**: "무단 사용 허용 손실 한도 = 100,000원" 입력(대표가 자유 변경). 저장하면 안내문구 "한도의 50% 경고, 70% 자동 차단".
5. **접속 허용 IP 등록**: 사내 대역(예: `10.0.0.0/16`)과 VPN 대역(예: `10.8.0.0/24`)을 CIDR로 등록한다. 회사 외부 직원은 VPN을 거쳐 VPN 대역 IP로 들어온다. 이어서 직원 A, B에게 게이트웨이 토큰(가상 키)을 발급한다. 직원은 공급자 키를 **받지 않는다**.
   - 검사 규칙: `출발 IP ∈ 허용 대역` **그리고** `유효한 게이트웨이 토큰`일 때만 통과.
- 프론트가 보여줄 것: 크레덴셜 카드(방식·상태·마스킹), 한도 입력 폼, 허용 IP 대역 목록(내부/VPN 구분 라벨), 직원 토큰 목록.

### 장면 2. 정상 운영 — "직원이 쓴다" (40초)
1. 직원 A 터미널: `curl gateway/v1/chat/completions` (게이트웨이 토큰) → 응답 성공.
2. 직원 B도 호출. 허용 대역 밖 IP에서 같은 토큰으로 호출하면 **403 + 대시보드에 거부 로그(출발 IP 표시)**(접근 통제 시연, 5초).
   - 노트북 1대 시연 시: `localhost`(127.0.0.1)를 허용 대역에 넣고 노트북의 LAN IP로 접속하면 거부되게 해 대역 밖 호출을 흉내 낸다.
3. 대시보드 **실시간 차트**: "게이트웨이 기록"(파랑)과 "공급자 보고"(주황) 두 선이 거의 겹침. 차액 게이지 ≈ 0원, 상태 **NORMAL**(녹색).
- 프론트가 보여줄 것: 서비스/PC별 호출·토큰·원화 비용, 두 선 차트, 차액 게이지, 상태 배지.

### 장면 3. 유출 — "대표가 토큰을 마음대로 재사용" (30초)
1. 내레이션: 대표가 K1을 게이트웨이 밖 개인 프로젝트 `.env`에 복사해 쓰다가 공개 저장소에 올림.
2. 연출: 화면 한쪽에 "GitHub에 노출된 K1" 장면(정적 이미지 or 스니펫).
- 이 단계는 시스템이 아직 모른다 = 문제의 핵심("탐지 지연").

### 장면 4. 공격 — "공격자가 유출된 키를 쓴다" (30초)
1. 공격자 터미널에서 스크립트 실행(대표가 버튼으로 트리거해도 됨): K1으로 **공급자에 직접** 호출, 초당 5회 × 건당 800원 ≈ 4,000원/초.
2. 게이트웨이를 거치지 않으므로 게이트웨이 로그에는 **0건**, 공급자 사용량만 오른다.
3. 대시보드: 주황선만 치솟고 파랑선은 평평 → 차액 게이지가 오르기 시작.
   - 차액 10,000원 이상(대략 3초 후): 상태 **SUSPECT**(노랑) + "설명되지 않는 사용량" 경고.
   - 차액 50,000원(한도 50%): **경고 알림** 토스트.
- 프론트가 보여줄 것: 차액 게이지(경고선 50%, 차단선 70%, 한도 100% 눈금), 차액 원화 숫자 실시간 증가.

### 장면 5. 자동 차단 — 하이라이트 (30초)
1. 차액이 한도의 70%(70,000원)에 도달(약 17초). 폴링 지연(최대 3초 ≈ 12,000원)을 더해도 **82,000원 안팎에서 멈춰 한도 100,000원 미만**.
2. Gateway가 자동 수행(타임라인에 단계별 시각 표시):
   1. 위험도 판단: `BREACH`
   2. K1 폐기: Mock Provider에 revoke 호출 → 공격자 스크립트가 **401** 받고 실패(터미널에 보임)
   3. 예비키 S1을 PRIMARY로 승격
   4. 사고(Incident) 생성 + 관리자 통보(화면 배너/토스트)
3. 대시보드: 상태 **BLOCKED**(빨강) 전환, 주황선 평평해짐, **"차단됨. 손실 82,000원 / 한도 100,000원"** 요약 카드.

### 장면 6. 복구 — "서비스는 안 멈춘다" (30초)
1. 직원 A가 방금처럼 호출 → **계속 성공**(내부적으로 S1 사용, 직원은 아무것도 바꾸지 않음).
2. 대시보드 상태 **RECOVERED**(녹색), 사고 상세: 탐지 시각, 차단 시각, 차단까지 걸린 시간, 손실액, 폐기된 키, 전환된 키.
3. (대조) WIF 크레덴셜 K2: 같은 방식으로 탈취해도 토큰이 15분 후 만료·재발급되고 공격자는 새 토큰을 못 만든다는 점을 **한 줄 설명 카드**로 마무리. 라이브 시연은 하지 않음.

## 3. 핵심 로직 (구현 기준)
- 차액(원) = 공급자 보고 비용 − 게이트웨이 기록 비용 (같은 크레덴셜, 직전 정상 시점 이후 누적).
- 허용 오차: 진행 중 요청/집계 지연분 5,000원은 무시(데모 상수).
- 판정: `차액 < 한도×0.1` NORMAL / `≥ 0.1` SUSPECT / `≥ 0.5` 경고 알림 / `≥ 0.7` BREACH → 자동 대응.
- 차단선을 70%로 둔 이유: 대조 주기 지연 동안 늘어나는 손실을 흡수해 **최종 손실이 한도를 넘지 않게** 하기 위함.
- 비율(10/50/70%)은 코드 상수. 대표가 바꾸는 값은 한도 하나뿐.

## 4. 프론트 화면 / 이벤트 계약 (대략)
| 화면 | 필요한 데이터 |
|---|---|
| 1 크레덴셜·한도 설정 | 크레덴셜 목록(방식, 마스킹, 상태, role), 한도 값 |
| 2 접속 허용 IP·토큰 | 허용 CIDR 목록(내부/VPN), 직원 토큰(최초 1회 노출) |
| 3 라이브 대시보드 | 시계열 2종(게이트웨이/공급자 비용), 차액, 상태, 최근 거부 로그 |
| 4 사고 상세 | 타임라인(탐지→경고→폐기→전환→통보), 손실액, 소요시간 |
- 실시간은 폴링 1~2초로 충분(SSE/WebSocket 불필요).

## 5. 의도적으로 뺀 것 (PoC 컷)
- 실제 OpenAI/Anthropic/Gemini 연동, 실제 WIF 연동 (Mock STS로 대체)
- 사용자 로그인/권한(대표 1명 가정), 다중 조직, 알림 외부 채널(이메일·슬랙)
- 장치 단위 인증(핑거프린트, 키 서명, mTLS): IP 대역+토큰으로 대체. VPN 자체는 구축하지 않고 "VPN 대역 IP"를 허용 대역으로만 등록(운영 확장 시 장치 인증 추가)
- 허니키: **선택 장면**. 시간이 남으면 장면 2 말미에 "가짜 키로 게이트웨이 접근 시 즉시 경고" 10초 추가. 기본은 컷.
- 테스트 코드: 대조/판정 함수에만 assert 1개.

## 6. 확정 필요
1. 위 한도 비율(경고 50% / 차단 70%)과 오차 5,000원으로 가도 되는지
2. 공격 장면을 **대표 버튼 클릭**으로 트리거(권장, 안정적) vs 별도 터미널 라이브 실행
3. 허니키 선택 장면을 넣을지
4. 직원 클라이언트는 터미널 curl vs 프론트의 간단한 "채팅 테스트" 화면(프론트 담당이 만들 시간이 있으면)
5. (확정됨) 화이트리스트 = 사내 IP + VPN 대역 CIDR 허용 + 게이트웨이 토큰. 게이트웨이 앞단에 프록시가 있으면 `X-Forwarded-For` 신뢰 설정이 필요하니 배포 구조 확인 필요(PoC는 직접 접속 가정)
